# Risk register

| ID | Risk | Type | Likelihood | Impact | Mitigation | Trigger to act | Status |
|----|------|------|-----------|--------|------------|----------------|--------|
| R1 | Seam design leaks: a provider calls the SDK directly and the unit suite silently depends on a tenant | technical | med | severe | Adversarial test greps `src/` for SDK calls outside the two seams | any direct call found | open |
| R2 | Offboard order wrong: license removed before mailbox conversion, mailbox lost | product | med | fatal | `dependsOn` edges from license removal and from license-carrying group removals to the mailbox conversion; the plan file is sealed, so steps cannot be reordered | tenant test shows mailbox soft-deleted | open |
| R3 | Secrets (temp password, TAP) land in plan file, audit log or verbose stream | security | med | severe | Secrets returned only as SecureString on the apply result; adversarial test scans every output for a seeded value | any hit | open |
| R4 | Stale or drifted plan applied: state changed between plan and apply | product | high | severe | Per-step fingerprint over the target and `before`, with fields that change on their own left out; apply refuses on mismatch unless `-Force`, and `-Force` never passes a create whose target exists; a step whose desired state already holds is skipped without a drift verdict; 24h max plan age | drift test fails | open |
| R5 | Exchange V3 cmdlets unavailable on macOS/Linux | technical | low | severe | Spike 0001 showed the module loads; cmdlets are REST-backed after connect | real-tenant run fails on macOS | open |
| R6 | Group-based licensing and dynamic groups cannot be removed directly; provider throws instead of explaining | product | high | moderate | The builder reads each group's license assignments, orders removals from license-carrying groups after the mailbox conversion and leaves them out under `-SkipLicenseRemoval`; dynamic groups are reported, not touched | tenant test | mitigated |
| R7 | Shared mailbox over 50 GB or on hold loses data after license removal | product | med | severe | `Mailbox.SharedEligibility` check step warns; `-SkipLicenseRemoval` documented | warning never fires | open |
| R8 | Device wipe hits a personal device | security | low | fatal | Default policy wipes corporate-owned only, retires personal; destructive steps need `-Confirm` or `-AllowDestructive` | ownership field missing in Graph response | open |
| R9 | Self-offboard or break-glass account offboarded | security | low | fatal | Refuse when the subject is the signed-in account or in `protectedUsers` (matched by object id, user principal name or mail), before step one of every apply, for every account a step would change; warn on Global Administrator | test | mitigated |
| R10 | Gallery publish from CI with a bad secret or wrong version | operational | med | moderate | Release workflow only on a published GitHub release; version from tag, passed through the environment and never into script text; dry-run job first | failed publish | mitigated |
| R11 | Graph throttling (429) during a 30-step apply leaves a half-applied plan | operational | med | moderate | Seam retries with Retry-After up to 3 times; plan status `PartiallyApplied` + resume | tenant test | open |
| R12 | Pester 6 breaks the suite | technical | low | minor | Pin Pester 5.x in build script and CI | CI red after upgrade | open |
| R13 | Plan file edited by hand and the integrity value recomputed | security | low | severe | The integrity value is a hash, not a signature. A resealed plan is a new plan and is held only by the preflight checks: tenant id, policy hash, target kind and action per provider, protection for every account a step changes, already-applied, and the destructive prompt built from the provider's own description. Remaining gaps: a resealed step that uses an action its provider allows on a target the snapshot cannot tell apart, and the recorded protected list when `-Policy` is not given. Signed plan files are the full answer | an edited plan file applied against the fakes | open |

For each `fatal` risk there is a piece of work that retires it (R2 and R9: the plan builders, R8: the device and OneDrive providers).
